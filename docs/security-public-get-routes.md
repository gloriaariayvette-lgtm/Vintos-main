# House public GET route inventory — AUTH-01 review candidate

Funnel **stays enabled**: `https://aegis.tailaa3de5.ts.net:8443` → `127.0.0.1:8500`. Network origin is not identity.

This is a source-complete decorator inventory of the house server and its registered domain, Watch, desktop, avatar and study modules; it does not call memory endpoints or expose their returned content. “Returns” describes code and field names, never live data. Duplicate declarations are retained because order matters. Conditional registration and import failures mean source declarations are not proof of live availability. Earlier live evidence is in `security-audit.md`; production was not changed to test this proposal.

The existing source broadly exposed GET reads unless handlers checked credentials. AUTH-01 gates **every** GET/HEAD before handlers, including mounted assets, framework `/docs`, `/redoc`, `/docs/oauth2-redirect`, `/openapi.json`, and future/dynamic routes. This closes anonymous history, conversation/context, memory search, journals, dreams, wants, inner life, biography, lab notes, stored media and diagnostic reads without deleting state or stopping autonomous jobs. Sealed Atelier rules remain authoritative and unchanged; a house identity does not override them.

Public exceptions after approval: `/`, `/app/` (enrollment shell only); the explicit manifest, lifecycle, avatar, voice and enrollment JavaScript assets listed below; `/api/client/capabilities` (feature advertisement); `/avatar-models/*` and `/models/*` (static public model assets). `/static/*` is protected because the directory can hold generated private pages. These are positive exceptions, not an `/api` wildcard. Asset directories must remain free of private generated files.

A valid independent Watch bearer retains only song/landing/latest/framing reads; `/api/watch/live` still needs owner identity. Private media is available with a short-lived signed capability: Watch links bind the exact path; owner browser tickets permit only media prefixes. Food review links retain the existing one-proposal expiring capability, validated by their existing handler. Token access is authorized access, not anonymous public memory access.

Token/query values are stripped before application/access logging. WebSocket tickets use subprotocols, not URL parameters. Provider credentials never appear in the enrollment response.
